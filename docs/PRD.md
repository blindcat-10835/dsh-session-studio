# 会话管理插件 PRD v1.0

> 术语以 [CONTEXT.md](../CONTEXT.md) 为准；用户故事原文见 [US.md](./US.md)；**交付前的逐条实现审计见 [PRD-AUDIT.md](./PRD-AUDIT.md)**。本地环境依据：182 个历史会话 / 15 个工作目录，日志合计约 237MB（压缩）。

## 1. 目标与非目标

**目标**：把会话从“一条条列表项”变成可分组的资产视图；用 AI 把批量命名与打标签从重复劳动里拿掉，且任何 AI 写入都必须先预览。

**非目标**：不改写原生左栏会话浏览器的分组；不做会话内容全文检索（属于官方搜索）；不做多用户/远端协作；不引入额外模型凭据；不动会话事件流格式。

**v0.3 边界（实测确认的能力上限）**：原生左栏「分组方式」菜单是硬编码的三项（按工作区/按工作区树/单列表），没有插槽也没有注册接口，插件**无法**往里加“按状态/按标签”；原生会话右键菜单只能**追加**条目，不能隐藏或重排原生项；因此 v0.3 的策略是「复用原生菜单 + 只加不改地补三处」——标签子菜单（右键）、行尾状态徽标、悬停卡信息。

**v0.3.1 边界**：分组顺序（§7.6）是插件面板自己的视图状态，只存浏览器 `localStorage`，不进宿主 `state.json`、不跨设备同步；拖动只作用于「组与组之间」，组内行固定「最新在前」。

**v0.3.2 边界**：标签词表（§7.7）是可编辑的用户数据，住在宿主 `state.json` 的 `tagDefs` 里：改名会**合并**（目标名已存在时两个词变一个，旧的 `createdAt` 保留），删除会连带清掉所有会话的 `tags`/`suggestedTags` 与规则里的该词，但**不动会话本身**。标签颜色、层级、别名仍不做（M2）。

## 3. 状态词表（唯一真源）

优先级自上而下，先命中先赢：**待处理 > 运行中 > 阻塞 > 失败 > 已完成未读 > 中断 > 完成**。

| 状态 | 判定来源 |
|---|---|
| 待处理 | 实时 `pendingInteraction` ∈ {approval, plan-review, question}（仅客户端可得） |
| 运行中 | 实时 `running`（仅客户端可得；宿主列表的 running 作为兜底） |
| 阻塞 | 日志尾部最近一次 `turn/end.reason = blocked` |
| 失败 | 最近一次 `turn/end.reason` ∈ {error, max-tokens} |
| 已完成未读 | 实时 `completionUnread`（仅客户端可得，且只对非当前会话） |
| 中断 | 最近一次 `turn/end.reason` ∈ {interrupted, aborted}（用户主动取消也算中断，不是失败） |
| 完成 | 其余：`completed`、`forked`，以及没有可读 turn 结束原因（null）的会话——“没有中断证据就算完成” |

> v0.2 变更：原“空闲”一档取消，按“最后一轮是正常收尾还是被打断”拆成完成/中断。理由：空闲把“正常结束”和“我取消了”混在一起，恰恰是用户最想区分的一件事。

叠加标记不参与状态：已归档、已固定。

## 4. 数据模型（插件自有状态，原子写 JSON）

```jsonc
{
  "schema": 1,
  "sessions": {
    "<sessionId>": {
      "tags": ["bug", "华为"],
      "suggestedTags": ["排查"],
      "note": "",
      "titleLocked": false,
      "titleSource": "ai",
      "intent": "开发",
      "updatedAt": "ISO"
    }
  },
  "tagDefs": { "bug": { "name": "bug", "source": "manual", "createdAt": "ISO" } },
  "rules": [
    {
      "id": "r-1", "name": "华为项目", "enabled": true,
      "match": { "keywords": ["华为"], "fields": ["title", "firstMessage", "cwd", "note"], "mode": "any" },
      "action": { "tags": ["华为"], "mode": "suggest" },
      "createdAt": "ISO"
    }
  ],
  "settings": {
    "ai": { "batchSize": 8, "concurrency": 2, "maxSessionsPerRun": 50, "readContent": true, "titleMaxChars": 48 },
    "status": { "tailEvents": 120, "concurrency": 3 }
  }
}
```

标签规范化：trim、内部空白折叠、长度 ≤ 24、大小写不敏感去重（保留首次拼写）、去掉前缀 `#`。

**状态索引**（`status-index.json`）：`{ "<sessionId>": { revision, lastTurnEnd, updatedAt } }`。用 `sessionPersistence.stat(id).revision` 判断是否需要重读。

## 5. 标签规则语义

- 条件字段：标题、首条人类消息、工作目录路径、备注（多选；`mode: any` 任一关键词命中即可，`mode: all` 要求全部命中）。
- 关键词匹配：大小写不敏感的包含匹配。
- 动作：`mode: suggest`（默认，只写 suggestedTags）或 `mode: apply`（直接加标签，但从不删除已有标签）。
- 求值时机：手动预览/应用、面板打开时对无标签会话的惰性建议，不做后台常驻扫描。

## 6. AI 流水线

- 路由：宿主 `ctx.get('llm')` + `ctx.get('agentDefaultModel')`；缺失时返回 503 `llm_unavailable`，面板置灰并给理由。不引入新凭据。
- 输入：会话标题 + 首条人类消息（截断 800 字）+ 工作目录名；不发送工具结果与助手长文。
- 重命名：每批 8 个会话，输出严格 JSON 数组 `[{id,title,reason}]`；标题 ≤ 48 字、单行；解析失败则该批标记失败并在预览里显示原因。
- 打标签：闭集优先——候选词表 = 现有标签；建议模式下可引入新词，但新词只进 suggestedTags，每次最多 2 个。
- 意图：与打标签同一次调用顺带产出（闭集六类：开发/排查/调研/文档/运维/其它）。
- 跳过：运行中、空白、子代理、已锁定（重命名）、已归档（默认）。
- 并发 2、单次上限 50 条、整体超时 120s；批次失败不阻塞其它批次，逐条回报。
- 写入：重命名走 `sessionController.rename({sessionId, title})` 并记录 titleSource='ai'；打标签只写插件状态。
- **异步化（v0.2）**：AI 重命名预览、AI 标签/意图预览、应用重命名、补齐缺失标签这四类操作不再占用单次 HTTP 请求，改为创建**任务**（§7.4 / §8.2）后由宿主顺序执行、逐条回报进度；客户端轮询任务进度，离开面板再回来仍能看到结果。单条手动改名、小批量直接追加/替换/清空标签仍为同步请求。

## 7. 交互规格

**入口**：侧栏 `sidebar.panellist`（id `session-studio`，order 40）→ 主面板 `main`（key `session-studio`）。

**页面结构（自上而下）**：
1. 页头：标题 + 刷新 + 索引进度（非阻塞）。
2. 概览条：待处理/阻塞/失败/已完成未读 四个可点计数（点击=切换对应状态筛选）。
3. 工具栏：搜索框；分组切换（状态/时间/标签/不分组）；自定义分组顺序时的「恢复默认顺序」；归档视图；“AI 批量重命名”“AI 补齐标签”“规则”按钮。
4. 筛选条：状态多选片、时间桶片、标签多选；右侧“清除筛选”。
5. 分组列表：组头（拖动柄 ⠿、折叠箭头、组名、总数、状态计数点、↑/↓ 微调）；行（复选框、状态点、标题、标签 chip、建议标签虚框、相对时间、「详情」按钮、「⋯」菜单）。**右键**打开原生共享菜单（§7.2）；只有插件能做的事——编辑标签、编辑备注、移入回收站——放在「⋯」菜单里，因为原生菜单不能承载插件自己的对话框。
6. 批量条（有勾选时浮出）：已选 N；重命名(AI)、追加标签、替换标签、清空标签、归档、删除、清空选择。

**对话框**：AI 重命名预览（旧→新、依据、跳过原因、逐条取消）、AI 标签预览（建议 chip 可编辑）、标签编辑器、规则编辑器（列表 + 表单 + 命中预览）、备注编辑、删除确认（说明进回收站）、回收站（列表 + 恢复）。

**空/错状态**：无会话、筛选无结果、索引进行中、AI 不可用（给理由 + 仅用规则的退路）、接口失败（可重试）。

### 7.1 行交互与选中

- 单选：单击行任意非交互区即选中（虚框高亮），选中行是快捷键的作用对象；`↑`/`↓` 在行间移动选中，`Enter` 打开详情。
- 双击行（或菜单「打开会话」、选中后按 `Ctrl+Enter`）＝跳转到会话：调用客户端 `uiWorkspace.openSession(sessionId)`，与原生左栏点击行为一致。空白会话、回收站中的会话不可跳转（菜单项置灰并给原因）。
- 行内「详情」按钮、右键菜单「查看详情」（面板在场时出现）打开面板内右侧分栏（§7.3），不改变当前会话选择。

### 7.2 右键菜单（复用原生共享菜单）

**v0.3 做法**：面板行右键不再画自己的菜单，而是用 `ctx.contextMenus.open({kind:'session', value:{sessionId, displayTitle}}, {x,y})` 弹出**原生共享菜单**——和原生左栏行右键是同一个弹层、同一套条目、同一套键盘行为。原生的 置顶/重命名/分叉/复制 Session ID/在文件夹显示/归档 全部原样可用。

插件以 `ctx.contextMenus.register` **追加**两个条目（只能加，不能删或重排原生项）：

| 条目 | 出现条件 | 行为 | 依赖 |
|---|---|---|---|
| 标签 ▸ | 总是 | 二级子菜单列出全部标签定义，已打的打 ✓；点一下切换（`POST /tags` + `menus.notify`）；没有任何标签定义时给一条禁用的“还没有标签（在会话管理面板里创建）” | 插件 `/tags`、`/sessions/:id/value` |
| 查看详情 | 面板在场（`panelBridge.active`） | 在面板内右侧分栏打开该会话详情（§7.3） | 插件内状态 |
| 打开会话 | 面板在场且有 `uiWorkspace.openSession` | 跳转到该会话 | `ctx.uiWorkspace.openSession` |

**面板行的「⋯」菜单**（不是右键）：原生条目 + 插件专属三条（标签编辑、备注、移入回收站）。理由：备注/标签编辑/删除要打开插件自己的对话框，而原生菜单的条目只能是按钮 + 子菜单，不能把对话框搬进原生弹层（D15）。

规则：追加项的 `order` 取 500（标签）与 550（面板项），落在「复制 Session ID」(450) 与「归档会话」(600) 之间；条目的 `failureLabel` 保证 `run` 抛错时有原生失败提示。原生菜单本身仍按它的规则禁用不可用项；插件不隐藏任何原生条目。

回退：`contextMenus` 不可用（旧宿主）或 `open()` 抛错时，退回 v0.2 的自绘 `RowMenu`（同一套服务调用），保证老环境仍能操作。

### 7.3 右侧详情分栏（面板内）

- 实现：**面板内主从分栏**（左列表 + 右详情栏，约 340px，窄屏改为覆盖式抽屉），由插件自己的状态驱动；不再使用右栏页类型。
- 内容：标题（可就地重命名）、状态点与状态名、工作目录（可点击在文件夹显示）、更新时间/创建时间、标签（可就地增删）、意图、备注（可就地编辑保存）、首条人类消息摘要、最近一轮结束原因、会话 ID + 复制。
- 操作：打开会话、分叉、归档/取消归档、移入回收站、AI 给这条建议标题/标签（单条同步调用）。
- 数据：优先用已加载的行数据（模块级缓存 + 行内数据）；打开时按 `GET /sessions/:id/value` 补齐首条消息与备注。会话被归档/删除后，详情栏显示失效提示并保留关闭按钮。
- 打开/关闭：行内「详情」、右键「查看详情」、选中行 `Enter` 均可打开；`Esc` 或关闭按钮收起，焦点回到原行。

> v0.2 实测修正：原方案是「向右侧栏注册页类型」。但在主栏被插件面板占用时，`sidebarRight.openTab` 只作用于 on-screen Session 的已挂载 surface，实测直接抛 `sidebarRight: no session surface is mounted`，用户点「查看详情」只会看到一个失败提示。分栏改为面板内实现后无这类依赖，也不需要用户先离开列表。

### 7.4 后台任务 UI

- 工具栏右侧“任务”指示器：有任务执行时显示 `spinner + 进度 (done/total)`；没有进行中任务时显示最近一次结果的状态点（成功/失败/已取消/已中断），点击展开任务列表。
- 任务列表：进行中置顶，展示类型、进度条、创建时间、取消按钮；已结束任务保留最近 20 条，展示结果摘要（成功 N / 失败 M / 跳过 K）与逐条明细入口（失败项可展开原因）。
- 任务完成时：若用户已离开列表，仅在指示器上标结果点，不弹模态；正在浏览相关视图时静默刷新行数据（1.5s 内合并一次）。
- 取消：`POST /jobs/:id/cancel`，正在进行的单条请求允许完成，随后不再发起新条目；已写入的条目不回滚（UI 明示“已应用的 N 条不会撤回”）。
- 轮询：有进行中任务时每 800ms 拉一次 `GET /jobs?active=1`（以及当前展开任务详情），无进行中任务时停止轮询；**打开任务面板时额外拉一次 `GET /jobs`**，否则面板打开前就结束的任务会看不到（实测踩到）。

### 7.5 原生左栏行装饰（v0.3，只加不改）

原生会话行有两个「座位」可以放插件内容，两者都只拿到 `sessionId`，不允许绑定或持有 Session：

| 座位 | 位置 | 插件放什么 |
|---|---|---|
| `sidebar.session.row.trailing` | 时间标签之后、置顶标记之前，非交互图标位；悬停/聚焦/菜单打开时隐藏（无悬停设备常显） | 状态点 + 标签数（如 `●2`），`title` 给「标签：a、b」或状态名 |
| `sidebar.session.row.hover` | 悬停卡中，相对时间与原生状态行之间 | 「状态名」一行（复用语汇与配色）+ 标签 chip 行 |

数据：一个批量探针 `GET /session-meta?ids=…`（一次最多 300 个 id，60ms 内合并同帧的所有行请求，结果缓存 30s）。装饰是纯只读的：不改原生分组/排序/点击行为，也不写入任何会话状态。

不做的：原生「分组方式」菜单（按工作区/树/单列表）是硬编码数组，插件加不进去（D13）；原生行本身的分组结构不改写（沿用 v0.1 的目标：分组留在插件面板里）。

### 7.6 分组顺序（v0.3.1 拖动排序）

- **拖动**：组头的 ⠿ 柄可拖（HTML5 drag & drop）。拖到另一组上时，被拖组落在目标组的位置上（先摘出、再插到目标下标）；拖动中源组 `.sm-group-dragging` 降透明度，目标组 `.sm-group-drop` 描边高亮。
- **键盘 / 点击等价物**：每个组头右侧有 ↑ / ↓ 两个 20×20 按钮，一次移动一格；首组 ↑、末组 ↓ 置灰。不做只能拖的交互。
- **按维度记忆**：顺序按分组维度分别保存（状态 / 时间 / 标签 三份互不干扰），存在 `localStorage` 的 `dsh-session-studio.group-order` 键里，形如 `{"status":["status:running","status:completed"]}`。刷新页面、切换维度后仍生效；同一浏览器多标签共享。
- **新组不丢**：保存的顺序里没提到的组（新出现的状态桶、新建的标签）按自然顺序排在已保存组之后，绝不因为“不在记忆里”而消失。
- **恢复默认**：分组的自定义顺序非空时，工具栏出现「恢复默认顺序」按钮，只清当前维度那一份。只有一个组时不出拖动柄与 ↑/↓（无可排序）。
- **不改数据**：顺序纯前端视图状态，不写会话、不写标签、不调接口；排序只影响分组之间，组内行仍按「最新在前」。

### 7.7 标签管理界面（v0.3.2）

入口：面板工具栏「标签管理」（在「规则」与「回收站」之间）。一个宽对话框，管的是**词表**（`tagDefs`），不是“谁身上有哪些标签”。

- **列表**：每个词一行——名字、来源徽标（手动 / 规则 / AI）、用量（「N 个会话」；有未采纳建议时补「N 条建议」）、创建时间。按用量从多到少排，同量按名字排。
- **新建**：顶部输入框 + 「新建」，回车即提交；同名（大小写不敏感）视为非法，给错误文案而不是静默成功。
- **改名**：行内「改名」把名字变成输入框（回车提交、Esc 取消）。**重名即合并**：目标词已存在时两个词合成一个，所有会话的 `tags`/`suggestedTags` 与规则里的该词一起改写成目标名，旧定义的 `createdAt` 保留。
- **删除**：行内「删除」先变成二次确认（写明会从 N 个会话和引用它的规则上移除、会话本身不受影响），确认后才提交。删除后若某条规则的 `action.tags` 变空，该规则一并删除（否则会变成“命中但不打任何标签”的空转）。
- **搜索**：按名字过滤当前列表，只影响显示。
- **写入立刻可见**：词表改动后通知面板刷新（`onChanged`），标签写入也会广播给面板——所以“右键打标签 → 面板还是旧的”这个 v0.3.1 的毛病不再出现（§7.1 的刷新合并 1.5s）。
- **同名建议不再重复显示**：某个词一旦成为真标签，同名的“建议标签”就没有信息量了。宿主在 `sessionOf` 读取时就把它剔除（旧 `state.json` 里已经存在的重复对也随之消失，不回写盘），客户端 `decorateRows` 再兜一遍；写入侧 `apply`/`renameDef` 也同步清理。

一致性：词表 CRUD 全部在宿主侧执行并落盘（`state.json`），客户端只发 `{op,name,to?}`、拿回整份新词表；不存在“客户端自己拼一份”的情况。理由见 ADR-0009。

### 8.1 任务（Job）

四个异步端点的返回都是同一种对象；`POST` 返回 202，客户端随后轮询 `GET /jobs/:id`。

```json
{
  "id": "job-1730000000000-a1b2c3",
  "type": "rename.apply",
  "state": "running",
  "params": { "items": [{ "sessionId": "s-1", "title": "新标题" }] },
  "total": 3,
  "done": 1,
  "failed": 0,
  "skipped": 0,
  "percent": 33,
  "createdAt": "ISO",
  "startedAt": "ISO",
  "finishedAt": null,
  "error": null,
  "result": null,
  "itemsTruncated": false,
  "items": [{ "key": "s-1", "state": "done", "message": null, "data": { "sessionId": "s-1", "title": "新标题" } }]
}
```

- `type` 闭集：`ai.rename`（预览；result=`{items,model}`）、`rename.apply`（result=`{applied,failed}`）、`ai.tags`（预览；result=`{items,vocabulary}`）、`tags.fillMissing`（result=`{candidates,updated,dryRun}`）。
- `state` 闭集：`queued` → `running` → `succeeded` / `failed` / `cancelled` / `interrupted`（宿主重启时把未完成任务置为 `interrupted`，不自动重跑）。
- 进度按条目回报；`percent = total ? floor(100*done/total) : 0`，进行中最多 99。
- 并发：任务之间串行（同一时刻只跑一个任务，避免 AI 请求与日志读取互相抢），任务内沿用 §6 的批次并发 2。
- 「补齐缺失标签」的 `dryRun` 也只是任务参数：任务 result 给出候选数量，不写状态。
- 失败语义：单条失败不终止任务，计入 `failed` 并记录 `message`；只有无法开始（参数非法、会话全部缺失、AI 不可用）才使任务 `failed` 并给 `error:{code,message}`。

## 9. 持久化

- 数据目录：`$DSH_HOME/storages/session-studio`（可用环境变量 `DSH_SESSION_STUDIO_DIR` 覆盖）。
- `state.json`、`status-index.json`、`trash.json`、`jobs.json`：临时文件 + rename 的原子写；写盘去抖 300ms。
- `jobs.json`：`{schema:1, jobs:[job]}`，保留全部未完成任务 + 最近 50 条已完成任务（超出丢弃最旧的终态任务）；进度写盘去抖 400ms，任务结束立即刷盘。
- 启动时把 `queued|running` 的任务改为 `interrupted`（`error.code='interrupted'`），不自动重跑。
- 回收站数据：`<dataDir>/trash/<sessionId>/`（整目录搬移，含原始 `session.lock` 与日志）。

## 10. 偏离与假设

- **D1（删除）**：DSH 没有会话删除 API。US18 的“删除”实现为移入回收站（移动会话目录），支持批量恢复；真正抹除需手工清理回收站目录。若会话的磁盘目录已不存在（历史遗留、手工清理、后端换存储），删除退化为 **tombstone**：只写回收站条目并把会话从列表隐藏，恢复时撤销条目——`GET /trash` 的 `tombstone:true` 会提示“原始数据已不在磁盘上”。
- **D2（子代理会话）**：默认不展示、永不参与批量；提供“显示子代理会话”开关仅作查看。
- **D3（多标签分组重复）**：标签分组下一个会话会在多个组出现；界面注明“按标签分组时会话可能重复计数”。
- **D4（AI 不可用）**：没有配置模型路由时 AI 按钮置灰，规则与手动操作仍可用。
- **D5（原生左栏）**：v0.1 不改原生会话行；行级装饰留到 v0.2。
- **D6（状态索引）**：失败/阻塞/中断依赖日志尾部索引；索引完成前这些会话先按“已完成”展示，完成后自动刷新（不显示伪状态）。
- **D7（右键菜单：v0.3 起复用原生）**：v0.2 的判断“原生菜单只能作用于原生行”**已被推翻**——`ctx.contextMenus.open({kind:'session', …})` 允许任何调用方弹出同一个共享菜单，`register` 也能给 `target:'session'` 追加子菜单。v0.3 因此改为：右键一律走原生弹层，插件只追加「标签」「查看详情」「打开会话」；自绘 `RowMenu` 降级为 `contextMenus` 不可用时的回退。残留限制：追加项只能加，不能隐藏或重排原生项；子菜单的勾选状态来自插件读盘，改动后需重新打开菜单才能看到最新 ✓。
- **D8（详情是面板内分栏）**：原设计用右栏页类型（`sidebarRightTabs` + `sidebarRight.openTab`），但右栏只服务“当前屏幕上的会话”，主栏被插件面板占用时没有 surface，实测抛 `sidebarRight: no session surface is mounted`；v0.2 改为面板内主从分栏，代价是详情无法与原生右栏同时占屏，同一时刻只有插件分栏可见。
- **D9（任务不跨进程恢复）**：任务进度持久化，但宿主重启不重跑；重启前正在执行的那个任务最多丢失“已写入的条目”的进度记账，已发生的写入不回滚。
- **D10（快捷键作用域）**：Ctrl+Alt+G / Ctrl+Shift+F / Ctrl+Alt+A 只在插件面板获得焦点且存在选中行时生效，不注册为全局快捷键，避免与原生左栏抢占。
- **D11（回收站仍是对话框）**：v0.2 的行菜单先把普通面板行接通；回收站仍是 v0.1 的对话框列表，所以回收站视图里的“恢复/彻底删除”菜单只以纯函数形态存在（未挂到真实行），且“彻底删除”固定禁用并给出原因——客户端没有永久删除路由（D1 已说明要手工清理目录）。
- **D12（任务 404 = 中断）**：客户端轮询任务时若宿主回答 404（任务已被清理），本地把该任务记为“已中断”，停止轮询，避免界面卡在“进行中”。这是稳健性补充，不改变 PRD §8.1 的宿主语义。
- **D13（“分组方式”菜单不可扩展）**：原生左栏「分组方式」（按工作区/按工作区树/单列表）与「排序方式」是 `ui-workspace` 里的硬编码数组，没有槽位、没有注册表、没有 `contextMenus` target，插件**无法**往里加「按状态」「按标签」。因此这两种分组只存在于插件面板（§7 分组切换）；原生左栏只获得 §7.5 的装饰。若将来原生提供插槽，可直接复用面板里已有的分组实现。
- **D14（原生菜单只加不改）**：`contextMenus` 的条目按 id 合并，同一 target 内 id 重复会失败；插件无法删除或重排原生项，也不做“覆盖式替换菜单”。这是刻意选择：原生项的行为、快捷键、可访问性由原生维护，插件只补它没有的（标签/详情）。
- **D15（标签的新建仍在面板里）**：右键子菜单只做“从已有标签里勾选”，不提供“新建标签…”输入（原生菜单条目是纯按钮，塞输入框会破坏键盘与焦点契约）；新建/改名/删除标签仍走面板的标签编辑器。子菜单在没有任何标签定义时显示禁用说明指路。
- **D16（标签写入靠广播桥回灌面板）**：原生子菜单、详情分栏、批量条这些入口不经过 Page 的 React 状态，写盘成功后由 `notifyTagWrite(ids)` 广播一次（清 `metaCache`、重置词表缓存、重新探针、触发 1.5s 合并刷新）。代价：面板关闭时广播无人接收（无意义，也不算 bug）；面板打开时最多滞后一个合并窗口。
