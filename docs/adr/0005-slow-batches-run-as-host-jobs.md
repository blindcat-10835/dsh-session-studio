# ADR-0005：慢批量操作作为宿主后台任务

- 状态：已采纳（v0.2）
- 日期：2026-11-11

## 背景

AI 重命名预览、AI 标签预览、应用重命名、补齐缺失标签这四类操作要读取多个会话的日志、分批调用模型，本机 185 个会话的实测里单次可能十几秒到分钟级。它们原先是一个同步 HTTP 请求：浏览器要一直挂着、超时即丢结果；面板切走或刷新后进度不可见；关掉页面就等于放弃。

## 决策

1. 宿主新增**任务**（Job）概念与一个串行执行器 `host/jobs.js`：`start/get/list/cancel/activeCount/recover/stop`，任务之间 FIFO 串行，任务内部并发沿用 AI 配置。
2. 四个同步端点改为「创建任务 → 202 + job」，客户端轮询 `GET /jobs?active=1` 与 `GET /jobs/:id`；结果（预览清单、应用结果）挂在 `job.result`。
3. 任务持久化到 `jobs.json`（进行中全量 + 最近 50 条终态），进程重启后未完成任务置为 `interrupted`，**不自动重跑**。
4. 单条手动改名、小批量标签增删仍走同步请求：它们只写插件状态或一次 controller 调用，几十毫秒级，做成任务只会增加一次轮询。

## 后果

- 浏览器不再需要为长操作保持请求；离开面板、切会话、刷新页面后仍能看到任务与结果。
- 代价：多了一层状态机与持久化；用户可能看到「任务失败但前 N 条已写入」，因此 UI 必须显式说明已应用条目不回滚（PRD §7.4）。
- 串行队列牺牲了「同时跑多个 AI 任务」的吞吐，换来可预测的日志读取与模型并发，避免两个任务把宿主的并发配额打满。
