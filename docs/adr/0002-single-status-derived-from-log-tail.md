# 会话状态是单值派生词表；失败与阻塞从日志尾部读出

官方实时状态只给出运行中、待处理（审批/提问/计划评审）、已完成未读；失败与阻塞只存在于会话日志的 turn 结束原因里。因此状态收敛为七档单值词表，按“待处理 > 运行中 > 阻塞 > 失败 > 已完成未读 > 中断 > 完成”取第一档；实时三档用官方状态，失败/阻塞由本插件读取每个会话日志的尾部切片派生，并用持久化 revision 做增量缓存。代价：首次要为历史会话读一遍日志尾部（本机约 237MB 压缩日志），期间界面显示索引进度；状态与日志可能有一秒级偏差。

## 修订（v0.2）

原先第六档叫“空闲”，把正常收尾（completed/forked）与被打断（interrupted/aborted）混在一起。它掩盖了用户最想区分的一件事——“这一轮是好好结束的，还是我中断的”。v0.2 把它拆成**完成**与**中断**两档，优先级上“中断”先于“完成”（互斥，仅由 `turn/end.reason` 决定）；没有可读结束原因的会话按“完成”处理（没有中断证据即视为完成）。词表总数因此由六档变为七档，实时三档与日志派生的机制不变。
