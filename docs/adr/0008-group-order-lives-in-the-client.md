# ADR-0008：分组顺序只存客户端，并存成「按维度的 key 列表」

- 状态：已采纳（v0.3.1）
- 日期：2026-11-12
- 相关：PRD §7.6、US32、§11 M1.3；ADR-0003

## 背景

用户要求「运行中 / 中断 / 完成 要求能够上下拖动」。也就是分组列表的**组与组之间**要能改顺序。三个候选做法：

1. 把顺序写进宿主 `state.json`（像标签规则一样当成用户数据）。
2. 存 `localStorage`，只当视图偏好。
3. 不持久化，只在本次会话内记住。

同时还有一个隐含问题：分组是**派生**出来的——状态组来自 `deriveStatus`，时间组来自 `bucketOf`，标签组来自 `tagDefs` 与每条标签。用户拖动时"这一组"到底是什么？如果用数组下标（第 0 组、第 1 组），那么筛选一变、标签一加，下标指的就是别的组了。

## 决策

1. **顺序是视图状态，存 `localStorage`，不进 `state.json`**：它只影响这台浏览器的显示，不影响任何会话、标签或规则；换设备、换浏览器不该强制继承别人的分组顺序，也不需要为它写迁移、备份、并发合并。宿主的 `state.json` 继续只放"真正的用户数据"（ADR-0003）。
2. **以组的 `key`（`status:running` / `time:today` / `tag:bug` / `untagged` / `all`）排序，不用下标**：`applyGroupOrder(groups, keys)` 给每个 key 一个 rank，未出现的 key 排在已出现的之后并保持它们的自然顺序。这样新状态桶、新建标签、筛选变化都不会让顺序错乱或让组消失。
3. **三个维度各存一份**（`{status:[…], time:[…], tag:[…]}`）：每张视图有自己的习惯顺序，"按状态"排好的顺序不该被"按标签"拖乱。
4. **拖动 + 键盘等价物都给**：HTML5 drag & drop 绑定在 ⠿ 柄上（不是整行，避免和行的点击/双击/右键打架），并给每个组头 `↑`/`↓` 按钮。拖是主路径，↑/↓ 是无鼠标、键盘用户、以及自动化测试能走通的路径——不做只能拖的功能。
5. **提供「恢复默认顺序」**：只清当前维度那一份；不提供隐式的"长按清除"，避免用户忘了自己改过顺序。

## 后果

- 顺序不跨设备同步，也不参与宿主的原子写与去抖——这是刻意的，代价是"换浏览器要重排一次"。
- `applyGroupOrder` / `moveGroupKey` / `moveGroupBy` 是纯函数（不改输入、不读环境），单测直接覆盖边界：空列表、null、未知 key、拖到自己身上、首尾不可再移。
- `localStorage` 在隐私模式或被策略禁用时会抛错，因此 `readGroupOrder` / `writeGroupOrder` 都做了 try/catch 与 `window.localStorage` 兜底：读写失败只退化顺序，绝不让面板崩。
- 拖动只重排**组**，组内行仍按「最新在前」（`sortRows`）；行级拖动是另一件事，没有做。
